# Mail delivery abstraction

Northstar can send a plain-text message through SMTP, or append it to a local outbox that a test can read. Production with no SMTP configuration does not pretend to send. No paid mail service is required, and no mail package was added. No existing test was deleted or weakened. There is still no forgot-password flow and no email verification.

## What was done

`resolveMail` in `src/lib/mail-config.ts` reads `MAIL_TRANSPORT`, `SMTP_URL`, `MAIL_FROM`, and `MAIL_OUTBOX`.

- `off` or `disabled` stays off, even when SMTP variables are set.
- An unknown `MAIL_TRANSPORT` stays off.
- `smtp`, or any non-empty SMTP URL, sends only when the URL is `smtp://` or `smtps://` and `MAIL_FROM` is an email address. A missing or invalid value stays off.
- `outbox` outside production appends JSON lines to `MAIL_OUTBOX`, or `.mail/outbox.jsonl` when that is unset. Production refuses the outbox.
- Production with neither SMTP variable set stays off. Development and test, with no SMTP settings, use the outbox. The default From address `Northstar <northstar@localhost>` is used only outside production.

`sendMail` in `src/lib/mail.ts` returns `{ ok: false, mode: "disabled" }` without creating the outbox file. A rejected recipient, a subject with a line break, or an empty body returns `ok: false` and writes nothing. SMTP errors return `{ ok: false, mode: "smtp" }` instead of throwing into the page. Success is `ok: true` only after the server accepts the message, or after the outbox line is appended.

`src/lib/mail-smtp.ts` speaks SMTP with `node:net` and `node:tls`. It sends EHLO, STARTTLS when the server advertises it, AUTH PLAIN, and a dot-stuffed `text/plain` body. Implicit TLS uses `smtps://`. Certificate checks stay on. The client does not set a TLS server name when the host is an IP address. `src/lib/mail-outbox.ts` writes one JSON object per line: from, to, subject, text, and `createdAt`.

The account page keeps the sentence that this page does not email a reset link. It adds a status line. With mail off, the exact text is “Email delivery is not configured, so features that send mail stay off.” The password form’s description points at that line. `.env.example` documents the four variables. `.gitignore` ignores `.mail/`. The README production note points here instead of saying a mail provider is still required.

## How it was verified

2026-11-27, after the change, on Node v22.23.4. Commands: `npm run lint`, `npm run typecheck`, `npm test`, `npm run test:e2e`. Playwright retries stay at 1 in CI and 0 locally. A retry is not a pass.

Unit tests in `tests/unit/mail-transport.test.ts` cover the production, development, and explicit modes. They read two outbox messages back, and they check that a disabled production config and a header-injection subject do not create the file. SMTP is a local server in the test process. One test delivers through AUTH PLAIN, including a body line that is only a dot. A wrong password returns `ok: false` and leaves the message unqueued. A second test upgrades with STARTTLS and opens `smtps://` against a certificate generated by `openssl` in a temp directory. That call passes `rejectUnauthorized: false` only into `sendSmtp`. The same certificate is rejected when verification stays on. `sendMail` itself does not expose a way to skip verification.

`npm run test:e2e` builds with `next build` and serves `next start` on `127.0.0.1:3100`. That process is production and has no `SMTP_URL`. The existing account test now expects the disabled sentence exactly. The other password assertions are unchanged.

## Problems found

The first `npm run lint` failed on `prefer-const` in `src/lib/mail-smtp.ts`. The second EHLO no longer reassigns `hello`, so the first binding is `const`. That was fixed before the suite above.

The first SMTP unit run also printed a Node deprecation: setting the TLS server name to `127.0.0.1` is not allowed by RFC 6066. The client now omits the server name for an IP host. The mail file was run again with no deprecation, and the suite above includes that change. No test assertion was weakened.

The in-process server accepted plain SMTP, STARTTLS, and implicit TLS on this machine. No external relay was required.

## Remaining limitations

- Nothing in the product sends a message yet. Forgot password and email verification are not built. The account page only says whether delivery is available.
- AUTH PLAIN is the only authentication. There is no AUTH LOGIN, no HTML part, and no attachment. The SMTP timeout is 8 seconds.
- Certificate verification cannot be turned off with an environment variable. A local self-signed relay needs a certificate the process trusts, or it will not send.
- The outbox is a JSONL file on the app’s disk. It is not a database table, and production will not write it.
- `docs/screenshots/change-password.png` was not recaptured, so it does not show the new status line.
- The title guard still matches only the draft, the loaded title, and the exact joined string. Board, list, issue detail, relations, saved views, and the new-issue dialog still call `router.refresh()` after their own saves.
- SQLite stays the default. The seed password is still `demo1234`. Rate limits are unchanged.
