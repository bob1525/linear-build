# Keyboard and screen-reader pass

The board, the list, the dialogs, the conflict prompt, and the change-password form now have names, focus, and keyboard paths that were missing. A row outside a windowed board or list is still not mounted. Arrow keys, Home, and End scroll that row into the window and focus it. No existing test was deleted or weakened.

## What was done

Windowed board cards and list rows expose `aria-setsize` and `aria-posinset`, so a mounted row announces its place in the full count. Each column is named by its heading. The list region is named with the issue count. Priority, an overdue date, and the assignee (including Unassigned) have names. The visible controls stay in the tab order.

From a card or row, Arrow Up and Arrow Down move to the previous or next issue. Home and End jump to the ends. On the board, Arrow Left and Arrow Right move to the neighboring column. The move scrolls the target into the window, keeps that one index mounted while it is focused, and focuses the title link without scrolling the page again. An open menu still owns the keyboard.

Dialogs are named by their heading and described by their description. Focus starts on the first field, Tab wraps inside the dialog, and closing returns focus to whatever opened it. Escape still closes the dialog, and still closes an open menu first.

The conflict prompt focuses Reload, which does not overwrite. Tab stays on Reload and Overwrite. Escape reloads. A click on the dimmed page returns focus to Reload and does not choose either action. A failed overwrite is an alert inside the description.

The change-password form is named by the page heading. The new-password hint is tied to that field. A failed submit marks the field the message is about and moves focus there. The success message can take focus.

## Problems found

The password test's `getByRole('alert')` matched two alerts: the form message "Passwords do not match", and Next's route announcer, whose text was "Change password · Northstar". The assertion is now scoped to the form. The form alert was already the right text. No product code changed for that failure.

## Remaining limitations

- A row outside the window is not in the tab order or the accessibility tree until arrow keys, Home, End, or scrolling mount it. The mounted row's `aria-setsize` is the full count. Select all still uses every filtered id.
- Dragging a card is still pointer-only. Keyboard users change status from the list menu or the issue page.
- Menu options are drawn outside the dialog, so Tab while a menu is open does not move through those options. Escape closes the menu before it closes the dialog.
- Contrast was not measured.
- There is still no email verification and no forgot-password flow. Those need a mail provider.
